## 1. What is running where

The application is **not** deployed the way a default Laravel app is. The cPanel
account `erpdhakawala` has a **split layout**:

| Thing | Path | Notes |
|---|---|---|
| Laravel application | `~/erp-app` | git checkout, `artisan` lives here, PHP runs from here |
| Web root (document root) | `~/public_html` | a **copy** of `erp-app/public`, served by LiteSpeed |
| PHP entry point | `~/public_html/index.php` | boots the app in `~/erp-app` |
| Static assets | `~/public_html/{build,images,css}` | **copied** from `erp-app/public` |
| Backups | `~/erp-backups`, `~/erp-build-backups` | do not delete |

**Consequence:** `git pull` inside `~/erp-app` updates the PHP and the *source* of the
assets, but **does not** update what the browser downloads. Blade emits
`/build/assets/app-<hash>.css`; if `~/public_html/build` still holds the previous hash,
that URL 404s and the whole site renders unstyled.

This has already happened once (30 Oct 2026) and cost an hour. It will happen again on
the next deploy unless someone syncs, so **every deploy must end with the asset sync**.

### Deploy checklist

```bash
cd ~/erp-app && git pull && php artisan optimize:clear
```

then (single copy-paste line, safe to run twice):

```bash
test -f ~/erp-app/public/build/manifest.json && echo "OK: app found" && mkdir -p ~/public_html/build ~/public_html/images ~/public_html/css && cp -a ~/erp-app/public/build/. ~/public_html/build/ && cp -a ~/erp-app/public/images/. ~/public_html/images/ && cp -a ~/erp-app/public/css/. ~/public_html/css/ && cp -a ~/erp-app/public/favicon.ico ~/public_html/favicon.ico && echo "OK: files copied" && HASH=$(grep -o 'assets/app-[^"]*\.css' ~/erp-app/public/build/manifest.json | head -1) && echo "CSS: $HASH" && curl -sI "https://erp.dhakawala.com/build/$HASH" | grep -iE "^HTTP/|content-type"
```

Success looks like `HTTP/2 200` **and** `content-type: text/css`.

> `php artisan storage:link` is **not** part of this deployment any more. Uploads
> (receipts, avatars) live on the private disk; the symlink would only re-expose
> `storage/app/public`, which is exactly what was fixed. See §4.

## 2. Assets: `public/build` is tracked on purpose

`.gitignore` deliberately does **not** ignore `/public/build`, because the cPanel host
has no Node.js toolchain. The compiled bundle ships in git.

**But** it is compiled output — if you edit Blade/CSS and add Tailwind classes, the
classes do not exist until the bundle is rebuilt:

```bash
npm ci && npm run build      # node 22; writes public/build/assets/app-<hash>.css|js
git add public/build         # commit the new hashes + manifest.json
```

A stale bundle is silent: the page still loads, the new utility class simply does
nothing. If a layout change "has no effect" in production but looks right in dev, this
is almost always why.

`public/css/brand-theme.css` is a separate hand-maintained Tailwind-subset bundle loaded
by `<x-brand-theme-style>`; it is not generated by Vite. Only touch it for brand colours.

## 3. Verification without CI

GitHub Actions minutes are exhausted — **do not** plan a change around CI being green.
Everything is verified locally. The sandbox has no `php` binary, so the suite runs on
`php-wasm` (`@php-wasm/node@3.1.61` + `node-8-4`), with `vendor/` reconstructed from
`composer.lock` zipballs. See `docs/RUNNING_TESTS_WITHOUT_CI.md` for the full recipe.

Minimum bar for any change:

| Check | Result expected |
|---|---|
| `phpunit tests` | `OK (158 tests, 619 assertions)` or more |
| `token_get_all(…, TOKEN_PARSE)` over `app/ config/ routes/ database/ tests/` | all ok |
| `php artisan view:cache` | compiles every Blade file |
| `php artisan route:cache` / `config:cache` | both build |
| `node -e '…'` / browser | not available — say so instead of pretending |

## 4. Do not regress these (each one was a real production bug)

1. **Demo sign-in personas** — `FirmLogin`, `PlatformLogin`, `AppShell` accept
   `partner@dhakawala.com` etc. with any password **only** when
   `config('erp.allow_test_logins')` is true. It defaults to false; only `phpunit.xml`
   sets it. Never gate this on `app()->environment('testing')` again — that turned one
   stray `APP_ENV=testing` into an open door to every firm.
   Test: `tests/Feature/FileAndLoginGuardTest.php`.
2. **Uploads are private** — receipts and avatars are written with
   `storeAs(..., 'local')` and served only through `routes/web.php` behind
   `auth` + `firm.member`, resolved by `App\Support\FirmFile`. Do not move them back to
   the `public` disk. `php artisan erp:privatise-uploads --dry-run` migrates old files.
3. **Invitation activation** is resolved from `invitation_token`, never from `?email=`.
4. **Timezone** is `env('APP_TIMEZONE', 'Asia/Dhaka')` — attendance, payroll and holiday
   boundaries all assume Dhaka.
5. **No hard-coded passwords** — every seeding/provisioning path generates one.
6. **Payroll period transitions** — a ledger must move out of `draft` when posted;
   reopening a locked period must work. Both are pinned by tests (they were broken).
7. **Attendance persistence** — failures are logged (`Log::error`), never swallowed by
   an empty `catch`.
8. **Console copy** — the platform console deliberately uses plain labels
   (Firms / Partner Units / Seats / Pending Setup) and plain integers (`1`, not `01`).
   The marketing words ("Cluster 01", "Zero-Trust Cluster", "Registered practice
   tenants") were removed on purpose. `tests/Feature/ConsoleCopyAndResponsiveTest.php`
   pins this; if you rewrite the dashboard, update the copy deliberately, not by accident.
9. **Attendance calendar** uses responsive classes, not an inline
   `grid-template-columns: repeat(7, 1fr)`. The inline version is unreadable on a 360px
   phone.

## 6. Conventions this project has settled on

- **Surgical edits.** Practice logic lives in six traits under
  `app/Livewire/Practice/Concerns/`; views are nine partials under
  `resources/views/livewire/practice/partials/`. Change the trait/partial for the
  feature, never rewrite the monolith.
- **User-facing language:** English UI, with Bangla labels only where the original
  design put them (e.g. notification recipient scope). The operator speaks Bangla —
  explanations to them are Banglish, code and commits are English.
- **Deploy commands must be a single `&&`-chained line.** The operator does not read
  code; give one copy-paste block plus "what success looks like" and "what to send me
  if it fails".
- **Commit messages** state the user-visible behaviour and the test that pins it.
